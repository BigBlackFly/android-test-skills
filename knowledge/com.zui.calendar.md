## 首次启动的三个弹框（pm_clear 后，顺序固定，实测 2026-09-11）

不知道这条会以为"主页打不开 / 更多按钮找不到"（167 探查连卡 3 轮的真正原因）：

1. **App 权限说明框**「日历需要使用以下权限」（必要/可选分组 + 退出/同意）
   - rid `com.zui.calendar:id/alertTitle`，同意 = `android:id/button1`
   - ⚠️ `wait_rid` 一命中就点会**点空**（入场动画未结束）：必须等 1.5s → 点 → **验证框消失**
     → 未消失则重试（dump 可证：不等待时第 1 秒与第 8 秒弹框原样还在）
2. **系统通知权限框**「日历正在尝试显示通知」（拒绝/允许）
   - rid `com.android.permissioncontroller:id/permission_allow_button_two`
   - **不在 `com.zui.calendar` 包内**，按 App rid 找必然找不到
3. **课程表功能引导框**「课程表上新了！」——触发时机是**`pm_clear` 后首次启动、在【日历主页】
   上弹**，**不是**"进入课程表功能时"（167 用例描述写的时机不同，内容一致）
   - 文案「课程表上新了！」/「点击快速导入课表，自动同步所有上课时间」/「我知道了」
   - rid `curriculum_guide_title` / `curriculum_guide_message` / `timetable_guide_button`
   - 点掉通知权限框后约 3-5 秒出现；进入课程表后逐秒观察 8 秒无第二个弹框

看门狗能兜底关掉 1、2，但**要看弹框本身就不能开看门狗**（开了等于清掉被测对象）。

## 导航入口

| 去向 | 走法 |
|---|---|
| 课程表模块 | 主页 → 右上角「更多」`iv_more`（无 desc；用 `_flow.tap_more_menu()`）→ 菜单「课程表」 |
| 周视图 `TimetableActivity` | 上一步的落点 = App 打开默认课表 |
| 全部课程表列表页 | 周视图 → 顶栏 `action_curriculum_table_settings`（文案「课程表设置」）。**进课程表不会直接到列表页**，用例说的"右上角菜单按钮"就是它 |
| 图库导入 / 拍照导入 / 手动创建 | 空状态页 `btnImportFromGallery` / `btnImportFromPhoto` / `btnCreateManually` |
| 新建课程表（**已有课表时**） | 列表页右上角 `action_add_schedule` |

⚠️ 已有课表时**不要**用 `_flow.goto_手动创建课程表()`：它内部走 `goto_课程表空状态()`，
已有课表时不是空状态 → 直接 BLOCKED「课程表非未添加课程表」。新建页 = `EditTimetableActivity`，
名称框 `et_schedule_name`。

## 全部课程表列表页（TimetableListActivity，185 实测）

- 标题「全部课程表」；列表项 `tv_schedule_name`（名称）/ `tv_default_badge`（「当前」角标）/
  `tv_schedule_info`（「设置」）
- 顶栏两图标：`action_schedule`（文案「编辑」= 用例说的"勾选按钮"）、`action_add_schedule`
  （文案「添加课程表」= "加号"）

### 设为当前课程表（186 实测）

- 确认框「**确定设为当前课程表吗？**」+ 取消(`android:id/button2`) / 确定(`android:id/button1`)
- 确定 → 「当前」角标移到选中行；取消 → 仅关框不改状态
- 删除弹框文案**随勾选数量变化**：多选时「确定要删除选中的 **2** 个课程表吗？」

### 删除全部课程表后的两种"空"（易错）

| 时机 | 落点 | 三按钮 |
|---|---|---|
| 删除全部**当场** | 列表空态 `TimetableListActivity`，「没有课程表」+「点击 + 创建新课程表」 | ❌ 无 |
| **重新进入**课程表 | 引导式空状态页 `TimetableActivity`，「还未添加课程表」 | ✅ 三个都在 |

删光后列表页**不会自动跳转**，要**离开再回来**（或重新冷启动进课程表）才回到引导式空状态页。
断言"空状态三按钮"必须补"重新进入"这一步，否则误判 FAIL。

### 多选态与置灰规则（本页核心）

点 `action_schedule` → 多选态：出现 `checkbox_select` + `bottom_bar` + `btn_set_default` /
`btn_delete`。**置灰规则（看 `enabled` 字段）**：

| 勾选情况 | btn_set_default | btn_delete |
|---|---|---|
| 仅勾选**当前**课程表 | `false`（置灰） | `true` |
| 勾选**多个**（含当前） | `false`（置灰） | `true` |
| 仅勾选**非当前**课程表 | `true`（可用） | `true` |

即：**勾选集合含"当前课程表" → 设为当前置灰**。删除弹框文案「确定删除此课程表吗？」⚠️ 不同于课程卡片的「确定删除此课程吗？」（那是删单条课程）。
- 新建的课表**不自动抢占"当前"**（185 复验成立）

## 标准链路

### 导入弹窗顺序（拍照/图库通用，先读这条）

点「拍照导入」或「从图库导入」后是**两段式、有先后**：

1. **App 内提示弹窗**「请确保图片清晰、完整」→ 点「知道了」
   - 日历自己的框，**与系统权限弹窗无关，无论权限是否已授予都会弹**
   - **必须关掉，否则后面什么都不发生**：不点掉，相机 25s 都不拉起、PhotoPicker 也不出现
   - 看门狗能兜底但有时序竞争（169 主用例赢过、独立用例输过）→ 显式关
     （复用 `_flow._dismiss_image_hint()`）
2. **系统权限弹窗**（相机/照片）→ **仅当对应权限未授予时才弹**；已授予则跳过
   - 未授予 → 按 policy 点「允许/拒绝」；按钮文案随"是否拒绝过"变化、必须正则匹配

测权限行为前若上一轮已允许过，需 `pm revoke` 重置前提，否则第 2 段根本不出现（revoke 后弹窗仍在，但「拒绝」已变为「拒绝并不再询问」）。

### 图库导入（到「确认课程表基本信息」页）

可复用 `_flow.goto_图库导入_基本信息确认页()`；完整链路实现在函数里，卡只记函数外差异：

- 解析需联网（约 20s），**轮询窗口必须 ≥60s**（`timeout=60`）；低于 ~20s 会在解析中途误判超时
- 素材 `/sdcard/Pictures/日历/课程表.png`，导入前先 `MEDIA_SCANNER_SCAN_FILE` 广播，
  否则 PhotoPicker 显示「无相册」
- **选图策略（勿回退"盲点第一张"）**：照片 tab 按媒体库时间倒序、所有缩略图共用
  `icon_thumbnail` 一个 rid → 第一张取决于媒体库最近有什么（其他用例拍照/截图会插队；
  `pm clear` 不清 `/sdcard`）。现由 `_flow._rank_thumbs()` 视觉排序 → 逐候选：裁剪页大图预检
  → 双态等待，最多 3 张。细节见 `_flow.py` 的 `_verdict_score` / `_ensure_grid`
- **解析失败弹窗（模态，非 toast）**：标题「图片内容不是课程表」+ 正文 + 「知道了」。这是
  **通用解析失败框**：选错图会弹、**真课程表云端解析偶发失败也弹**（同素材 2 分钟后成功
  实测）→ 不能断定图选错了。点「知道了」后回裁剪页（先查网格再 BACK，盲按会退出
  PhotoPicker）。预检通过的候选被弹此框 = 偶发失败 → 重试同一张；总次数上限 3 次，用尽
  BLOCKED，**禁止归因为"超时/需联网"**
- **目标页控件（断言用）**：名称 `et_schedule_name`（图库导入预填「学生课程表」，断言前
  `clear_text`）、完成 `btn_finish`、学期开始 `layout_semester_start_date`/
  `tv_semester_start_date`、当前周数 `layout_current_week`/`tv_current_week`、总周数
  `layout_total_weeks`/`tv_total_weeks`、周末有课 `switch_weekend_classes`、显示非本周
  `switch_show_non_current_week`
- **学期总周数弹框 = 滚轮选择器**（174 实测）：当前值居中高亮，上下各露 ±1；数字为 Canvas
  绘制 **dump 读不到** → 用 `ocr()` 定位数字坐标 `tap_xy` 点选（不支持点选则 `input swipe`
  上滑一格兜底）→「确定」后 `tv_total_weeks` 变化
- **必填校验（174 实测，与规格不符）**：名称清空后「完成」**不置灰**（视觉可点击、dump
  `enabled=true`），点击后**停留确认页被校验拦截**（与手动创建页一致）。规格写"必填为空完成
  置灰"时按用例记 FAIL 并注明"实际未置灰、点击被拦截"
  - **置灰断言**：日历的置灰是「整体变淡」，像素对比度法（`contrast_of` + `assert_grayed`）
    对整块变淡会误报 → 必须用 `assert_button_state_visual(rid, "grayed")`。置灰是视觉样式，
    UI 树 enabled/clickable 可能不变；以 case 预期为准，未配置视觉凭据时降级 WARN（不是 FAIL）
- 确认页展示值示例：学期开始 `2026年09月01日`、当前周数 `第2周`、总周数 `20周`；学期开始
  点开为系统 DatePicker（`android.widget.DatePicker`，「取消」关闭）

### 拍照导入（到相机拉起）

可复用 `_flow.test_camera()`。链路：空状态页「拍照导入」→ 提示弹窗「知道了」→ 相机权限弹窗
（未授予时）→ `com.zui.camera/.CaptureActivity`。

- **提示弹窗不关，相机 25s 都不拉起**（时序竞争见上）
- 从相机返回：返回键可能被取景器吃掉，`am force-stop com.zui.camera` 更快更稳；且退回的是
  日历主界面（不是课程表页），需重新走「更多 → 课程表」

### 手动创建（到新建课程表页）

可复用 `_flow.goto_手动创建课程表()`。链路只有一步（`btnCreateManually` →
`EditTimetableActivity`），坑全在目标页：

- 名称默认空且**必填**：不填点「完成」会被校验拦住（页面不动）；图库导入确认页才有预填名
- 保存 = toolbar 右侧 `save_view`（文本「完成」，clickable），**不是** `btn_finish`；
  `action_save` 是其不可点父容器
- **不要按 back 收键盘**——back 会直接退出 `EditTimetableActivity` 丢编辑
- 两个开关**默认均关闭**（177 实测 `switch_weekend_classes`/`switch_show_non_current_week`
  checked=false）；图库导入确认页「显示非本周课程」因导入样本可能默认开启，二者默认态不同
- ⚠️ **「新建课程表」页本身就是「课程表基本信息编辑页」**（178 实测）：同一
  `EditTimetableActivity`，含 名称框 + 学期信息 + 课程时间设置 + 课程提醒时间 + 两个开关。
  用例前提写"手动创建后进入基本信息编辑页"时，**停在本页即可，不要点「完成」保存**
- ⚠️ **点「完成」保存后的落点是周视图**（不是列表页），且**新建的课表名不会作为可点列表项
  出现**；按"列表页点课名进编辑页"寻路会 BLOCKED（178 首跑实测）

### 确认页导航关系（页面拓扑）

- 「确认课程表基本信息」页点左上角返回 → 「确认识别结果」页（`TempTimetableActivity`），
  **不是**课程表页也不是主页；要重进确认流程就再点「下一步」
- 识别结果页顶栏右侧没有图标，`_flow.tap_rightmost_icon()` 会退化匹配到左侧返回键，
  在该页不要用它找「更多」
- 确认页点「完成」→ 创建课程表 → 课程表列表（含「全部课程表 / <课表名> / 当前 / 设置」）；
  多课表时**每个课表名下各带一个「设置」**（170 实测）。「当前」标签跟在**原有**课表后面 ——
  新导入/新建的课表**不会自动抢占当前**

## 课程时间设置页

入口：确认页「课程时间设置」（副标题「设置课程节数，调整每节课时间」）。
Activity：`com.zui.calendar/.timetable.management.TimeSlotSettingsActivity`。

默认值都有独立 rid，**可直接 `read_rid` 断言，不用 OCR**：

| 字段 | rid | 图库导入路径 | 手动创建路径 |
|---|---|---|---|
| 每节课上课时长 | `tv_lesson_duration` | 30分钟 | — |
| 课间休息时长 | `tv_break_duration` | 10分钟 | — |
| 上午课程节数 | `tv_morning_slot_count` | 4节 | 4节 |
| 下午课程节数 | `tv_afternoon_slot_count` | 5节 | 4节 |
| 晚上课程节数 | `tv_evening_slot_count` | 0节 | 4节 |

**默认值因创建路径不同**（175 = 图库导入 / 178 = 手动创建）：报告中按实际路径断言，
跨路径断言会误判。

- 节次明细「第1节」与「08:00-08:30」是**两个独立文本节点** → 断言要分别匹配，别要求同一
  节点同时含「第」和「-」，否则永远匹配不到、把正常产品误报成 FAIL（175 首跑踩过）
- 两个时长弹框的内容区是 **Canvas 自绘**（`customPanel` 下无 dump 子节点），当前值读不到：
  只断言弹框打开（标题 + 取消/确定），数值用 `t.ocr(y_min, y_max)` 补读并记 INFO ——
  弹框半透明，OCR 会混入背景文字，**不可作断言**
- 「上午课程 / 下午课程 / 晚上课程」是**分组标题**（`clickable=false`），点了页面不动是正常
  设计不是 Bug；用例只要求"查看入口"时断言其存在 + 节数显示即可
- 返回确认页用 BACK 键；**别点本页「完成」**（会直接创建课程表）

### ⚠️ 必须「先读值再滑动」

**这不是方向问题，是视口问题**：元素不在当前视口时 `read_rid` 返回 `''`，按
`_num('')==None` 判会连报 FAIL（178 二跑血的教训）。顺序：

1. 进页面立刻读首屏 4 个值（上课时长 / 休息时长 / 上午 / 下午节数）
2. 再上滑读 `tv_evening_slot_count`（懒加载）
3. 步骤5 要断言的「默认时间显示」必须**在步骤2/3 改时长之前**采集快照

第 3 点尤其关键：节行时间随「上课时长/课间休息」**实时重算**——步骤2 把时长拨到 30 分钟后
所有节行变成 30 分钟制（08:00-08:30 …），此时再断言「上午第一小节 8:00-8:50」必然 FAIL
（断言的是被改动后的状态）。**更强的写法**：能"滚到可见再读"就不要依赖排好的读取顺序
（顺序脆弱、换方向就翻）。

### 入口 row rid = `layout_time_settings`（不是 layout_time_slot_settings）

实测（2026-09-11）编辑页入口行 rid 为 `com.zui.calendar:id/layout_time_settings`。
时长两行的**可点容器**是 `layout_lesson_duration` / `layout_break_duration`，
`tv_lesson_duration` / `tv_break_duration` 只是值节点（`clickable=false`），点值节点无效。

### 节行是共用 rid，按 y 排序定位第 N 节

所有小节共用 `item_container` / `tv_slot_number`（第N节）/ `tv_time_range`（时间）/
`iv_arrow`（可点，desc=编辑），**没有 per-slot rid**。定位第 N 节 = 取 `iv_arrow` 按
`bounds_xy[1]` 排序后取下标。跨屏读全部节行要逐屏下滚 + 并集累加（`screen_text()` 只返回
当前视口，一屏装不下 12 节）。

### 课程提醒时间入口在编辑页首屏

`layout_default_reminder`（可点行）/ `tv_default_reminder`（行内值）。入口在**编辑页
`EditTimetableActivity`**，**不在课程时间设置页**。

- 实测编辑页**首屏即可见**（在「课程时间设置」之下、布局底部）；知识卡曾写"需上滑一屏"
  是**按竖屏推的**，本机实测常在横屏下运行，该结论不成立（178 三跑实测）
- 默认 `5分钟前`
- 点开是 RadioGroup（非 Canvas，文本可读）：`不提醒 / 任务发生时 / 5分钟前 / 15分钟前 /
  30分钟前`，底部「取消」
  - ⚠️ RadioButton 的 `checked`/`selected` **本 ROM 不暴露在 dump 里**（视觉有绿色圆点，
    dump 节点是 False/缺）→ 别用 `find_nodes(checked=True)`；改读**确认页行内显示值**
    （选中即时更新行内，弹框里没有"确定"）或视觉断言绿色圆点
  - 点其它项即时换行内值；点「取消」/点外面关弹框都**保留新值**。关闭后用上滑/下滑定位该行
    读行内值

### 弹框滚轮：上课时长**循环**、课间休息**钳制**（2026-09-14 更正）

两个轮的边界行为**不一样** —— 原卡把两者都写成"循环"，是错的：

- **每节课上课时长**（`{30,35,…,120}`，每档 5）：**循环**。实测 `120 再拨 5 档 → 50分钟`
  （越界一档回绕到 30，再 4 档到 50）✅
- **课间休息**（`{5,10,15,20,25,30}`，每档 5）：**钳制**。实测 `30 再拨 5 档 → 30分钟`
  （停在边界不动）✅ —— 178 历史上偶尔观测到"回绕到 5"属**误判**：当时起点不是 30
  （上一步少拨/多拨过一档，而该步只记 INFO 没断言）

方向：**上=减小、下=增大**（两轮一致）。

所以「可选择 30-120 / 5-30」的验证姿势是：**拨到上端并核对到位 → 再越界多拨几档 →
断言值仍落在值域内**（循环与钳制都满足诉求），实际行为记 INFO。
**不要**断言"必然回绕" —— 178 实测 5 次 2 通过 3 失败，全是这条。

### 弹框里 OCR 偶发漏读 → 必须按次数点按，别让 OCR 进判定循环

实测：课间 10 拨到 5，目标 5 但 OCR 在弹框内返回 None → 脚本以为"没动"继续点 → 在循环上
绕圈 → 走满 `max_steps` → 原地打转 14 分钟（178 第一次跑卡在 Step2）。

**正确做法**：按档位次数点按（不读 OCR 反馈），点确定，读 UI 树文本
（`tv_lesson_duration`/`tv_break_duration`）作判据。见 `_flow.py` 的 `wheel_tap_steps` /
`apply_and_read` —— **所有"拨值 + 点确定后断言"的场景都应优先用这套共享能力**；示例见 `178.py`。

### 节数 ＋/－ 按钮是 ImageView，别用 OCR 找符号

「+」「－」是 ImageView 图形（OCR 读成 "4节•＋" 这种粘连文本）。固定 rid：
减号（desc=删除）`btn_remove_<morning|afternoon|evening>_slot`；
加号（desc=新建）`btn_add_<morning|afternoon|evening>_slot`。

### 晚上课程节数懒加载 + 下午小节时间

- 晚上节数首屏不渲染；直接 `read_rid(tv_evening_slot_count)` 拿到 None，需先 swipe 露出再读
- 178 case step5 写"下午第一小节 14:00-15:50"是 1h50min，与"上午 8:00-8:50（50 分钟课时）"
  不自洽 → 按 50 分钟课时应为 14:00-14:50，实测也是 14:50。报告按实际判 PASS + 注明疑似
  用例笔误

### ⚠️ 写用例脚本建议存成「无 BOM」UTF-8

**已不再致命**：`run_case.py` / `evals/*` 自 2026-09-14 起统一用 `utf-8-sig` 读源码，带 BOM
也能正确解析（此前带 BOM 会让 `ast.parse` 抛错 → `USER_INPUT` 提取为 None → 用例被判成
"辅助脚本"不入库）。仍建议无 BOM：多一个隐式状态就多一处跨工具差异。去 BOM 用
`[System.IO.File]::WriteAllBytes`，别用 PowerShell `Set-Content -Encoding UTF8`（会加 BOM）。

## 课程查看 / 编辑 / 删除（183 实测）

**页面拓扑（别走错）**

- 列表页**点课名 = 编辑课程表**（`EditTimetableActivity`），**不是查看**（183 首跑踩到：
  按周视图找课程卡片，等满 12s 仍为 0）
- 列表页 **BACK 一次 = 周视图**；再 BACK 一次 = 日历主页 `AllInOneActivity`。**这是从列表页
  到周视图最便宜的边**——别回主页重走「更多 → 课程表」（多 3 步），更别重跑「图库导入 →
  保存」（约 100s，纯浪费）

**课程卡片 → 编辑页是两段，不是一段**：点周视图课程卡片 `curriculum_card_view` → **先进
「课程列表」弹框** `CourseListActivity`（`clCourseDetail` / `tvFirstLine` 课程名 /
`tvSecondLine`「第1节 | 第1-20周」）→ 再点 **`ivEdit`**（desc=编辑）才进编辑页。直接按
"点卡片=进编辑"写用例会挂在找不到 `etCourseName`。

**删除确认框**：标题「确定删除此课程吗？」，取消 = `android:id/button2`，删除 =
`android:id/button1`。

- 断言用**课程数减少**，不要用"课程名消失"（同名课程有多门，删掉一个「语文」后列表里仍有
  「语文」）
- ⚠️ **基准必须在周视图上取**：编辑页里读不到 `tv_curriculum_title`，会拿到空列表；而
  `空集 ⊆ 任意集合` 恒真 → 「取消后课程仍在」会变成**无论是否真删除都 PASS 的假阳性**
  （183 首跑实测 `before=0 → 仍判 PASS`）。基准务必在 `_open_edit_page()` **之前**、回到周
  视图后取，且基准为空时按 WARN 处理而非 PASS
- ⚠️ **网格异步渲染**：进周视图立刻 dump 可能拿到空 recyclerView（183 首跑 FAIL「未找到课程
  卡片」，实际有 25 个）→ 按 rid 轮询等待，别一次性读取就下结论

### 图库选图的视觉排序（183 实测，2026-09-10）

**视觉排序必须看"确定度措辞"**（症状：连续 3 次 BLOCKED「未回到照片网格」，都选中了非课程表
图片）。根因：只比"高/中/低"等级 → 同级并列使 stable sort 退化成网格序（最前面往往是刚截的
桌面图）→ 选中模糊候选。修法见 `_flow.py` 的 `_verdict_score()`（等级分 + 否定词重罚 + 模糊
措辞降权 + 读出星期表头加分，**不能纯关键词计数** —— 否定句同样含关键词）与
`_safe_back()`/`_ensure_grid`（**IME 吞 BACK 是通用规律，适用所有 App**）。
效果：183 从 BLOCKED×3 → 一次解析成功 PASS 20/20。
